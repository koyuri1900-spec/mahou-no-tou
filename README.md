# 魔力の塔

タップと自動生産で魔力を育てる、スマートフォン優先の放置型クリッカーです。
HTML・CSS・素のJavaScriptだけで動く静的サイトです。ビルド工程も外部サーバーも不要です。

## 遊び方
- 中央の **魔力の結晶** をタップすると魔力を獲得します
- **ユニット**(精霊 → 魔術師 → ゴーレム → ドラゴンの卵)を買うと、毎秒魔力を自動生産します
- **強化** タブで、累積型強化(何度でも買える)と条件解放型強化(条件を満たすと1回買える)を購入します
- 購入数は ×1 / ×10 / 最大 で切り替えます
- ゲームを閉じている間も、生産量の100%が最大4時間分たまります(再訪時に自動加算)
- メニューから記録の確認、手動保存、リセット(確認あり)ができます

## 起動方法
ファイルは相対パスで参照しているので、どのフォルダに置いても動きます。

```bash
# どちらか
python3 -m http.server 8000      # → http://localhost:8000/
npx serve .
```
`index.html` を直接ダブルクリックしても起動します。ただし `file://` ではブラウザによって保存が効かない場合があるため、HTTPで配信して遊ぶのがおすすめです。

## 公開方法(静的ホスティング)
このフォルダの中身(`index.html`, `style.css`, `game.js`, `save.js`, `visuals.js`, `ui.js`, `assets/`)をそのまま置くだけです。サブディレクトリに置いても動きます。

- **GitHub Pages**: リポジトリにpush → Settings → Pages → Branch を `main` / `/ (root)` に設定 → `https://<ユーザー名>.github.io/<リポジトリ名>/`
- **Netlify**: https://app.netlify.com/drop にフォルダをドラッグ&ドロップ
- **Cloudflare Pages**: 「Direct Upload」でフォルダをアップロード(ビルドコマンドなし)

`tests/`, `tools/`, `worklog/`, `README.md`, `CHECKLIST.md`, `package.json` は公開しなくても構いません。

## 数値設計

### ユニット
| ユニット | 初期価格 | 1体の生産/秒 | 価格倍率 | 解放条件 |
|---|---|---|---|---|
| 精霊 | 15 | 1 | ×1.23 | 最初から |
| 魔術師 | 300 | 8 | ×1.25 | 累計魔力200 & 精霊1体 |
| ゴーレム | 15,000 | 100 | ×1.26 | 累計魔力12,000 & 魔術師5体 |
| ドラゴンの卵 | 1,500,000 | 1,800 | ×1.28 | 累計魔力1.2M & ゴーレム5体 |

- 価格 = `ceil(初期価格 × 倍率^所有数)`。まとめ買いの価格は1体ずつの丸め後価格の合計なので、表示額と実際の消費額は必ず一致します
- 最大購入は、連続近似で個数を見積もってから実価格で補正するため、残高が負になりません
- 一度満たした解放条件は、その後下回っても閉じません

### 累積型強化(何度でも購入可)
| 強化 | 効果(1レベルごと) | 価格 |
|---|---|---|
| クリック強化 | タップ獲得量 = (1+Lv) × 1.12^Lv | 25 × 1.9^Lv |
| 全生産量強化 | 全ユニット ×1.15(乗算で累積) | 500 × 2.6^Lv |
| 契約の絆 | 所有ユニット1体ごとに全生産 +0.2% × Lv | 8,000 × 3.5^Lv |

「契約の絆」は所有総数に比例するので、安い旧ユニットを買い足すことにも意味が残ります。

### 条件解放型強化(1回のみ)
| 強化 | 解放条件 | 価格 | 効果 |
|---|---|---|---|
| 精霊の祝福 | 精霊10体 | 1.5K | 精霊 ×3 |
| 結晶共鳴 | 累計魔力100K | 60K | タップ時に毎秒生産量の5%を追加 |
| 魔術師の秘伝書 | 魔術師10体 | 80K | 魔術師 ×3 |
| ゴーレムの核 | ゴーレム10体 | 3M | ゴーレム ×3 |
| 竜の目覚め | ドラゴンの卵10体 | 300M | ドラゴンの卵 ×3 |
| 塔の覚醒 | 毎秒生産2M | 5B | 全生産 ×2 |

### 想定進行(`node tools/simulate.js 1440 4` の結果。最初の10分は毎秒4タップ、以降は毎秒1タップ)
| 時点 | 出来事 |
|---|---|
| 6秒 | 最初のクリック強化 |
| 12秒 | 最初の精霊 |
| 44秒 | 最初の魔術師 |
| 約4分 | 最初のゴーレム |
| 約16分 | 最初のドラゴンの卵 |
| 約74分 | 条件解放型強化をすべて取得 |
| 1時間 / 4時間 / 24時間 | 毎秒 5.5M / 80M / 230M |

序盤は数十秒〜数分ごとに新要素が開き、1時間を過ぎると成長は緩やかになります(エンドレス)。

## 視覚演出(v1.1)

### ユニットの魔力運搬
| ユニット | 採取 | 運搬先 | 見た目 |
|---|---|---|---|
| 精霊 | 結晶の上空を漂う魔力を集める | 結晶 | 光の粒を抱えて飛び、尾を引く。納入すると結晶が光を吸収 |
| 魔術師 | 左の浮島付近の「魔力の泉」で詠唱(足元に魔法陣) | 塔の窓 | 紫の魔力球を浮かべて運ぶ |
| ゴーレム | 左下の「結晶の採掘場」 | 塔の扉 | 結晶の塊を担いで歩く |
| ドラゴンの卵 | 塔の足元で動かない | ― | 周囲の魔力を吸い寄せて脈打つ。10体以上(または「竜の目覚め」)で時々揺れる |

- **実際の魔力の増加は `game.js` の生産計算だけ**です。演出はそれを見せるだけで、納入の回数によって魔力が増えることはありません
- 画面に出るキャラクター数は所有数の対数で増えます(1体→1、2〜3→2、4〜7→3…)。上限は精霊6・魔術師4・ゴーレム3・卵1(控えめでは約半分)
- 所有数や生産量が増えると、作業の速さ、粒子の量、塔の窓の明かり、光の強さが増えます
- 各キャラクターは開始時期と所要時間がばらけているため、一斉には動きません

### クリスタルの成長段階
| 段階 | 名前 | 条件 | 見た目 |
|---|---|---|---|
| 1 | 微弱な結晶 | 開始時 | 小さくくすんだ結晶、光は弱い |
| 2 | 魔力の覚醒 | 累計魔力 2,000 | 大きく明るい結晶、内部に光が流れる |
| 3 | 高密度の魔力結晶 | 累計魔力 2M & ゴーレム解放 | 左右に結晶が生えた深い色の形、周囲を小結晶が回る、塔の屋根が光り、結晶から塔へ魔力の通路 |
| 4 | 魔力の極致 | 累計魔力 2B & ドラゴンの卵解放 | 中心に光の核、強い発光、足元と塔頂に魔法陣、浮遊結晶が増える |

- 段階は保存せず、累計魔力とユニットの解放状況(どちらも減らない値)から毎回求めます。そのため保存値と食い違うことはなく、魔力を使っても段階は戻りません
- シミュレーション(`node tools/simulate.js`)では、約1分で第2段階、約14分で第3段階、約52分で第4段階に達します
- 左上に現在の段階と、次の段階までの進捗(対数目盛)を表示します

### 塔の発展
- 窓の明かり: 所有ユニット6体ごとに1つずつ灯る(最大9)。強化レベルが上がるほど明るい
- 第3段階: 屋根の先端が光り、浮遊結晶と魔力の通路が現れる
- 第4段階: 塔頂に魔法陣、浮遊結晶が増える

### 出来事への反応
タップ(発光・粒子)、強化購入(結晶から塔へ光が走る)、新ユニット解放(魔法陣とお知らせ)、段階上昇(大きめの演出とお知らせ)。どれも1.6秒以内に終わります。

### 負荷対策
- requestAnimationFrame 1本で描画(標準30fps、控えめ20fps)。キャラクターごとのタイマーやDOM生成はしない
- 粒子は160個の使い回し、一時演出は最大12個
- タブ非表示中・画面外では描画を停止。復帰時に経過時間を一気に処理しない
- メニューの「演出」で 標準 / 控えめ / オフ を選べる(保存される)。端末で「視差効果を減らす」が有効な場合、新規ゲームは控えめで始まる
- オフでもクリスタルの段階や窓の明かりなど、成長の結果は静止画で表示

### セーブの変更
セーブ形式を v2 にしました(演出設定 `visualMode` を追加)。v1 のセーブは読み込み時に自動で変換され、進行状況はそのまま引き継がれます。キャラクターの位置やアニメーションの途中状態は保存しません。

## 数値の範囲と精度
- 魔力は JavaScript の number(倍精度浮動小数点)で扱います。初期版の範囲は **0〜1e300**。超えた値は1e300に丸めます
- 有効桁は約15桁です。1e15を超えると下位の桁は丸められますが、表示は上位3桁なので影響はありません
- NaN・Infinity・負の値は、すべての加算・減算・読み込みで安全な値に置き換えます
- 表示: 1,000未満は整数、以降は K / M / B / T / Qa / Qi / Sx / Sp / Oc / No / Dc、1e36以上は指数表記(例 `1.23e40`)。表示は切り捨てなので、所持額が実際より多く見えることはありません

## セーブ
- 保存先: `localStorage['mahou-no-tou.save']`(このブラウザ内のみ)
- 保存するもの: 魔力、累計魔力、タップ回数、各ユニットの所有数と解放状態、強化レベル、条件強化の解放/購入状態、購入モード、最終保存時刻、バージョン
- 価格・生産量は保存せず、毎回再計算します(二重管理による食い違いを防ぐため)
- 保存のタイミング: 購入時(即時)、タップなどの変化時(2秒に1回まで)、10秒ごと、画面を離れる/閉じるとき
- 読み込み時の検証: JSONが壊れていれば新規ゲームを開始し、元データは `mahou-no-tou.corrupt-backup` に退避します。負の所有数や型違いなどの個別の不正値は初期値に置き換え、内容をコンソールに記録します
- 保存できない環境(プライベートモードなど)でもゲームは遊べます。メニューに警告を表示します

## オフライン収入
`オフライン収入 = 最終保存時点の毎秒生産量 × min(経過秒数, 14400)`
- 復元直後に一度だけ加算し、すぐ保存して基準時刻を進めるので、リロードを繰り返しても重複しません
- 時刻が逆行している場合や、保存時刻が未来・不正な場合は0になります
- タブがバックグラウンドで止まっていた場合も、60秒を超える空白は同じく4時間で打ち切ります

## テスト
```bash
npm test                 # 単体テスト(Node.js 18以上): 価格・最大購入・残高・生産量・強化・オフライン上限・セーブ/復元・不正データ・リセット・成長段階・演出計画・セーブ移行
pip install playwright && python3 -m playwright install chromium
python3 tests/e2e.py     # ブラウザE2E: CHECKLIST.md の1〜17を実際の画面で操作して確認
python3 tests/e2e_visual.py  # 視覚演出のE2E: CHECKLIST.md の V1〜V9
node tools/simulate.js   # バランスシミュレーション
```
E2Eは `page.clock` で時刻を固定・早送りし、再現性を確保しています。

## 既知の制限・未実施事項
- **実機(iOS Safari / Android Chrome)での確認は未実施**です。スマホ表示はChromiumのモバイルエミュレーション(390px・320px)で確認しました
- スクロール中の誤タップ防止は `click` イベントの仕様(スクロール時は発火しない)に依存しており、自動テストでは再現していません
- セーブはブラウザ単位です。ブラウザのデータ削除で消え、端末間の同期はありません
- 1e300を超える魔力は扱いません(通常のプレイでは到達しない想定)
- 演出の見た目・発熱は実機で未確認です(自動テストは数・負荷・動作のみ確認)
- 1時間以降の成長は緩やかで、長期の目標(転生など)は初期版の範囲外です
- 見出しのドット調フォント(DotGothic16)は Google Fonts から読み込みます。読み込めない場合は標準フォントで表示され、動作には影響しません
